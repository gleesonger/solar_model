# Dashboard

For Markov DP, the Plan tab shows expected visible net cost and expected full-horizon score separately. Solar/Load selections, charts and details are fixed-condition stress illustrations; their net cost is labelled accordingly and their Excel exports include a report-basis column. They must not be probability-weighted using old scenario weights to reconstruct the objective. See the [Markov reporting contract](../implementation/markov-dynamic-programming.md#expected-results-and-illustrative-paths). Other planning modes retain their existing summaries.

For exact loaders, filters, intermediate frames, and batched SQL, see [dashboard data processing](../implementation/dashboard-data.md). For live/cache/client ownership and final table/chart/export structures, see [dashboard state and presentation](../implementation/dashboard-ui.md).

Source: [solar_model/dashboard/app.py](../../solar_model/dashboard/app.py), [solar_model/dashboard/layout.py](../../solar_model/dashboard/layout.py).

The favicon is the amber sun/panel in `solar_model/dashboard/assets/solar_power.svg`. Startup passes the source-relative file path to NiceGUI, which serves the SVG at `/favicon.ico` and references that URL in the page's icon link. The asset must be valid SVG; restart and reload after deployment. Browsers may cache the fixed icon URL.

## Current tabs

Plan detail column metadata lives in the insertion-ordered `PLAN_COLUMNS` dictionary in `dashboard/tabs/plan.py`, built from an aligned table of frozen `PlanColumn` dataclasses with every field explicitly supplied (no constructor defaults). It centralises labels, Compact order, formats, aggregation, browser score normalisation and Excel inclusion. Advanced order follows definition order; a single semantic aggregation flag controls interval splitting, hourly grouping and footer totals.

- **Recent:** Live/Today table; latest kW, daily meters, latest/BoD/raw forecast totals; past 7 days and past 12 months energy/economics.
- **Analysis:** lazily loaded energy, power, battery, per-array and money charts; range/grouping/Sum–Average controls; custom chart builder and downloads.
- **Plan:** latest or selected saved plan in one screen: today's date preloads today's snapshot choices while a blank Snapshot follows latest; selecting a saved snapshot pins its action, summaries, scenarios, chart and detail table. Private demonstrations and settings remain available.
- **System Info:** newest valid metadata value per variable, plus the app's first 12 Git commit characters (full hash in a tooltip; `unknown` for unstamped builds).
- **Control:** automatically saved holiday date ranges with an inclusive day count (a single entered date creates a one-day period), household-load forecast recalculation by selected months, confirmed tariff recalculation and managed restart actions.

Scheduled planning is owned by the independent `runtime.planner` process. The dashboard creates a separate private demonstration process only when requested. It has no startup solver warm-up and cannot schedule shared plans.

## Updates and state

- [DashboardSnapshotStore](../../solar_model/dashboard/snapshot.py) refreshes shared Recent data and device information in worker threads while browsers are connected, once per full interval after work completes. With no subscribers it waits without polling; the first connection loads data, and stale cached data refreshes on reconnect.
- Refresh failure retains the last successful snapshot. Successful refresh increments version and publishes to browser subscribers.
- Per-browser `DashboardState`/`DashboardElements` hold controls and element references. Snapshot application updates existing tables/labels; it does not rebuild tabs.
- Browser reconnect resubscribes and reapplies the newest snapshot.
- Live polling uses [LivePowerCollector](../../solar_model/dashboard/live.py); a per-browser timer applies readings at the configured live interval.
- Daily grid/PV baselines publish only after successful processing. Temporary failures retry without advancing the day or partially updating PV integration.
- The live table remains blank until successful data. Device daily meters drive solar/load/battery totals; grid totals subtract the first persisted same-day lifetime-meter reading or first live reading.
- Per-string voltage/current gives PV proportions. Live PV kW and daily array energy are allocated from plant solar totals using those proportions/integrals; they are not direct independent meters.
- Available battery energy comes from plant availability telemetry; SOC is shown separately.
- All three Recent tables include actual House Load. Live/Today uses measured load power for Latest, stored integrated house energy for Today (updated on full snapshot refresh), and the full saved daily house profile for BoD Forecast. Its Latest Forecast and Raw Forecast cells remain blank; the house forecaster has no separate versions for those columns. House Load Today resets on local date change. Past tables include house actual totals only, without a house-forecast column.
- Live/Today hides the separate Load row, whose Latest power duplicates House Load while its Today energy comes from the device load counter. The Past tables retain both Load and House Load energy.

## Queries, charts, exports

- [query adapters](../../solar_model/storage/queries/dashboard.py) owns summary/calendar/forecast helpers and adapters. [analysis SQL](../../solar_model/storage/queries/analysis.py) aggregates requested chart fields in SQLite and batches shared sources.
- Recent daily/monthly/lifetime summaries share one native SQLite aggregation of hourly actuals and selected forecasts. Python prepares calendar/timezone boundaries and formats the final small tables; it does not aggregate source measurements.
- Analysis Energy by hour includes House Load (Forecast), initially deselected, in House Load blue with the same hatching as Solar Forecast. Recent Live/Today shows the saved full-day house forecast only in its House Load row's BoD Forecast cell; the two Past tables omit house forecasts.
- Energy/cost charts normally use hourly rollups. Single-day telemetry retains minute points; longer ranges use hourly telemetry. Custom battery-level charts can query minute data.
- Analysis Energy includes **House Load** (estimated from load power), selected by default, and the original **Load** device counter, initially deselected. Both remain available in the legend/table/CSV; house load is also selectable in custom energy charts. Missing/long power intervals remain unavailable at storage level, though chart aggregation can display missing energy as zero. Recent actual summaries and economic calculations retain their existing load-counter inputs; forecasting now uses House Load.
- Analysis Power labels the measured household-demand series **House Load** in its legend and table; its internal DataFrame/CSV column remains `load`. Energy **Load** remains the device energy counter; **House Load (Forecast)** predicts household demand in Analysis and supplies the Recent House Load BoD cell.
- Import/export power is averaged from separately accumulated grid sign magnitudes, so alternating import/export cannot cancel both series. Meter-energy totals remain separate.
- Energy is summed; telemetry and rates use averages where appropriate. Custom `battery` means available energy level with a no-minute-record fallback; Analysis energy `battery_flow` means charge minus discharge.
- [ChartDataDisplay](../../solar_model/dashboard/components/chart_display.py) shares chart/table toggle, clipboard, CSV, labels, and totals. It preserves user legend state during normal updates.
- Analysis Energy, Power and Costs include a single series-selection button in their header toolbar. It starts at **Default** and cycles **None → All → Default**; Default restores the chart's original visibility choices. It preserves table/export data and zoom; individual legend entries can still be toggled. Other callers can opt in through `show_series_selection=True`.
- Analysis downloads support minute/hour/day/week/month/season/year, CSV or Excel, optional forecasts. Interval energy/costs sum; fields ending `_kwh` or `_watt_hours_day` use the last non-null reading, including battery availability levels; other numeric fields average (including cumulative forecast Wh). Import tariff bands retain distinct non-null labels in reading order, joined with ` / ` when an interval spans multiple bands. These are stored-field aggregates; see [metric semantics](../reference/metric-semantics.md) for chart/download differences. Excel strips timezone metadata while retaining displayed local time.
- Changing range/custom selection runs database work via `run.io_bound` and shows progress. Analysis is not automatically refreshed by shared Recent snapshots.
- Downloads aggregate raw samples directly in SQL and load only the selected forecast vintages; disabling forecasts omits their table entirely. A single native SQLite query returns the joined result to pandas; Excel output passes the whole pandas DataFrame to the Rust-backed XlsxTurbo writer, with no application row/cell writing loops. Large minute exports still contain every requested row/field, so their file generation remains more expensive than hourly/daily output.

## Freshness and notifications

- [warnings.py](../../solar_model/dashboard/components/warnings.py) publishes hidden timestamp metadata and sends a heartbeat every 5 seconds; [warnings.js](../../solar_model/dashboard/assets/warnings.js) owns one persistent bottom banner.
- Priority: offline → socket disconnected → heartbeat absent/older than 20 seconds → persisted data stale → live data stale.
- Persisted threshold = 3 × full interval. Live threshold = max(15 seconds, 3 × live interval). Missing timestamps count as stale.
- Brief tab switches retain a heartbeat within its 20-second timeout. Long suspension is detected from wall-clock age; disconnect/reconnect and offline/online events invalidate the heartbeat until a fresh one arrives. No repeated page reload loop is used.
- The hidden-by-default three-dot indicator pulses in repeating cycles for three seconds after a new live reading, using finite CSS animations. It clears on unhealthy connection/heartbeat/live readings, backgrounding, or suspension and checks its absolute expiry on resume. It indicates receipt of a live update, not continued connectivity; a stale persisted-data warning does not suppress healthy live activity.
- Below Live / Today, a small light-grey Last reading label always shows the reading date and time in the browser's local timezone, without a timezone suffix (or awaiting live data). Chrome saved offline pages may not execute dashboard scripts; the recorded timestamp remains useful, but the in-page banner/animation cannot guarantee current status in such a copy.
- Action errors use dismissible top notifications (10 seconds); info/success use 5 seconds. The banner remains until healthy, with a manual Reload action.

See [styling.md](styling.md) for visual conventions and [review findings](../reviews/findings.md) for limitations.

Presentation formatting lives in `solar_model/dashboard/formatting.py`; query records are independent of NiceGUI in `solar_model/storage/queries/types.py`. The unmounted Hourly tab, its chart renderers and unused navigation/state fields were removed during the package restructure.

## Plan tab

[PlanStore](../../solar_model/dashboard/plan_store.py) is a server-wide cache/subscriber hub for plans committed by the headless planning service. It polls the latest saved ID and service status every second, loads changed reports once, and publishes browser updates. Startup restores the last saved result. The planning service separately detects electrical updates, applies the configured cadence, persists successful plans and runs submission-time retention. See [saved plans](../implementation/plan-history.md).

Plan date and Snapshot selectors sit immediately right of Plan settings. On first load, Plan date is today in the configured timezone and today's snapshot choices load automatically; Snapshot stays blank to follow latest. The date remains editable and clearable. A historical selection stays pinned while new actual plans arrive; clearing a selector returns to latest. The existing action, summaries, scenario selectors, chart, tables and exports display the selected snapshot. Both views remain available for the configured retention period; legacy Compact-only snapshots use their saved hourly resolution.

Invalid externally edited configuration retains the last valid live planning settings and logs a warning once for that file revision. Automatic planning continues with those settings until a valid revision is saved.

[PlanTab](../../solar_model/dashboard/tabs/plan.py) owns each browser's optional override and presentation. Run Demonstration creates a private demonstration using those settings; its action caption includes the red text `[Demonstration - not part of actual plan, save config to disk to apply change]`. Load Global copies the live saved settings into the draft. Run demonstration always calculates a private demonstration, using the browser override or the live saved settings. It never changes the shared actual plan. Saving clears that browser's override. While following latest, every successful shared result replaces displayed demonstrations, preserving scenario/view/chart selections. A demonstration that finishes after a newer shared result is discarded. Unsaved settings do not affect scheduling or other browsers. The settings dialog closes and a spinner appears during browser requests; settings controls restore on success/failure. Shared refreshes also show the spinner while keeping previous results visible.

The chart has five logical series: Solar, House Load, Battery, Grid Import and Grid Export. Actuals are solid and forecasts dashed in the same colour, with one shared legend toggle per metric and tooltip labels distinguishing actual/forecast. Solar and household demand use kW on the left axis; predicted interval kWh are divided by actual interval hours. Stored battery energy uses kWh on the right axis; actual SOC times nameplate capacity matches the planner's initial-energy convention (rather than available-discharge energy). Actuals are queried separately from telemetry, from snapshot-local midnight through the earlier of now and the displayed projection horizon. They may overlap the forecast after its calculation time, including on historical plans, and refresh every minute while displayed. No actuals are stored in new plan snapshots; older embedded actuals are ignored. Missing-minute values remain null in the data; the chart joins recorded actual readings with a continuous solid stroke across missing samples so they cannot resemble forecast dashes. Forecasts come from the selected scenario. Refresh updates data on the existing chart, preserving selected legend series, zoom and Solar/Load scenario choices while updating the report summaries and details. Axis labels and tooltips use the configured timezone; the detail table displays local HH:MM only; full timestamps remain in the underlying result and chart.

The horizontally scrollable detail table has no pagination. Compact view is the default and groups core columns by configured-local clock hour, including partial edge hours; Advanced shows selected scenario columns at the original model resolution and appends lookahead rows (configured as four-hour MILP steps or hourly DP steps, with possible partial edge intervals). The chart also includes those extra 24 hours in Advanced; switching back to Compact restores the visible-day chart/table. Both include derived ending battery SOC beside stored kWh and a summed Losses column, with numeric cells and short unit-labelled headers. Header sorting is disabled, preserving chronological order. Switching detail views does not rerun the model; it updates chart series in place while preserving legend/zoom selections. Summaries use one bordered block of inline label/value pairs. On mobile, controls wrap and summaries stack; the five-tab navigation scrolls within the viewport. Numerical planning remains database-free. The shared report worker persists plans after calculation; demonstrations and the workbook CLI do not. Planning sends no device commands.

Scenario switches update the existing chart series in place, preserving legend visibility and zoom. Plan charts render without animation so complete forecasts are visible immediately after refresh.

Run Demonstrationing YAML changes through Plan settings starts a demonstration. Refreshing recomputes the plan and summaries from the latest available data, but does not guarantee different optimal totals. The optimiser can choose the same cost/protection outcome for several preference values. Plan rows remain in chronological order across midnight and repeated local hours; HH:MM display does not determine ordering.

The Compact Plan detail table has one grey bold Total row. Advanced has three footer rows: elapsed hours 0–24, hours 24–48 (or the remaining horizon), and the full Total. A period crossing the 24-hour boundary contributes to each subtotal in proportion to its duration; its terminal score belongs to the subtotal containing the period end. The rows sum interval kWh flows/losses and import cost, export revenue and net cost from unrounded model values. Timestamps (apart from the row label), tariffs, rates, power limits and opening/closing/minimum/maximum battery levels are blank; entirely missing energy columns remain blank.

Plan compilation, solver and total simulation timings are flushed directly to the dashboard worker's stdout, visible in the launching terminal or its redirected log.

Plan detail includes a **Plan action** column. DP records Self-consumption, Force charge or Force discharge for every period; the first policy is shared across scenarios and later choices are scenario-specific. MILP reports its first selected policy and later flow-based labels. The UI shows `Export Solar Excess` when a zero-rate Force charge or Force discharge row exports PV; for the first row it uses the requested ceiling, and for later rows it infers zero rate from battery flow. The top action label follows PV export in the selected scenario. The underlying model mode and results remain unchanged. Compact joins distinct actions within each hour; Advanced and Excel preserve selected-view labels.

**Download Excel** beside Plan detail exports the selected scenario to an `.xlsx` workbook, with the selected Compact/Advanced data columns, full configured-local Start/End timestamps (`YYYY-MM-DD HH:MM:SS`), plan actions, SOC, rounded numeric cells and the same selected-view footer rows. The display-only hours column is omitted and score columns retain original period contributions (in original chronological order). Hidden sorting fields are excluded. The filename uses the successful result's model and protection adjustment, explicit Solar/Load scenario names and configured-local plan start: `plan-MILP-protection-75-solar-high-load-low-20261031-1005.xlsx`. Pending control changes do not relabel the existing result's download; the worksheet is named Plan detail. Export reuses the shared XlsxTurbo writer and does not recalculate the plan.

All dashboard table headers stay below the dashboard topbar during page scrolling and leave the viewport at the end of their own table. Shared `assets/table_headers.js` translates the real header within the table bounds on scroll/resize, preserving column widths, sorting and horizontal scrolling without a second header or an inner vertical scrollbar. Updates use animation frames; child-list observation also handles newly displayed tables and refreshed rows. Styling applies to all Quasar table headers.

`dashboard.actuals_to_forecast` maps PV strings to unique forecast array names, such as `pv1: East`. Recent live labels use these names directly; `Config.actuals_to_forecast_panel_ids` resolves them for ID-based storage queries, allocation and chart columns. This configuration change needs no database migration.

Plan table numeric values use fixed decimal places: energy, cost and power use two, tariff rates four, and SOC one. Numeric cells remain numbers and use tabular digits; totals use the same display precision. Compact hourly flows/losses/clipping/costs sum, end battery/SOC use the hour-end level, tariff rates are duration-weighted, and distinct action/tariff names are joined. Crossing intervals are split in proportion to elapsed duration, with linearly interpolated battery levels at hour boundaries. Repeated DST hours remain separate. Charts, model results and summaries retain their original resolution; Excel follows the chosen hourly Compact or original-period Advanced view.

Solar/Load scenario controls offer exactly Low, Med and High with multipliers from `config.energy_plan.scenario_multiplier` (Med selected initially). They use individual bordered fieldsets with centred legends above the buttons. Unselected buttons use Quasar grey-2 with dark text; the selected button retains the primary colour and white text. The groups have a 24px gap (twice the former 12px) and wrap on narrow screens. Border/legend rules are scoped to `.plan-scenario-group`.

Advanced Plan detail displays Cost Score, Protection Score and Limit Score per hour for each original period; Terminal Score and Total Score show original period contributions because the terminal credit occurs once. Footer rows sum contributions, and all scores show two decimal places. Cost Score is negative net cost. Protection Score is the tariff/preference-scaled reward, using the selected optimiser's protection curve (MILP piecewise-linear, DP exact nonlinear) and duration weights; it is not the raw 0-100 protection utility. Total Score includes cost, protection and final-row terminal contributions. The selected scenario scores are unweighted. For MILP and independent-scenario DP, averaging visible and hidden scenario totals with normalised probabilities gives the overall optimisation objective (within solver tolerance). For Markov DP, these are stress-path scores; the objective comes from the dedicated expected result fields. Lookahead rows are excluded from the summary statistics and Compact chart/table/download, but included in the Advanced chart/table/download. Advanced subtotals separate the first 24 hours from the remainder; the final Total covers both portions. Compact omits score columns; Advanced Excel includes them.

Dashboard detail includes **hours** immediately after End: the row duration in elapsed hours (15 minutes = 0.25). Cost, protection and limit score cells are divided by this duration; terminal and total score cells retain original period contributions, as do energy/cost columns. Footer rows show the hours in each span and sum original score contributions using unrounded values. This is display-only: simulation result score contributions and exported score contributions remain unchanged. Excel omits the hours field; Advanced exports elapsed duration as Duration (min). Compact also shows hours for its partial/full clock-hour rows.

The on-screen Advanced Plan columns follow this reading order: timing/action; tariffs; household demand/solar generation; energy routes and inverter conversions; total losses and grid totals; battery constraints and ending kWh/SOC; finances; scoring. Solar, battery, load and grid routes use short directional headers such as **S→B**, with a flow key above the table. The battery-start, solar/battery-to-inverter and four individual conversion-loss columns are omitted from Advanced and its Excel export; the model still uses them to calculate the displayed total loss. Headers deliberately break before units. Start through Tariff retain their original widths; subsequent columns are 20% narrower than the previous Advanced styling and remain horizontally scrollable. A blank buffer follows the table so bottom notifications do not cover its last row. Compact is unchanged. New unlisted fields remain visible at the end of the on-screen table; Advanced Excel uses the fixed export mapping described below.

Compact Plan detail merges conversion losses and solar clipping into a single Losses (kWh) column, including its totals and Excel download. Advanced retains the separate conversion-loss total and clipping column.

Plan chart Solar, House Load and Battery forecasts use gently smoothed dashed lines. Grid Import and Grid Export forecasts use unsmoothed dashed steps, holding each interval value until its end; interpolation must not imply imports/exports during zero-flow periods. Model interval values, totals and exports are unchanged.

Startup and plan refresh share `dashboard.planning_worker.ensure_planning_worker()`: one asynchronous warm-up task is created and an early plan request awaits it while showing the normal spinner. Awaiting yields to the main event loop, so other tabs and live updates continue. Cancellation of one waiter does not cancel the shared task. Warm-up failures are logged and release waiting requests to attempt their normal plan run. Background plans and browser demonstrations share this one worker and execute sequentially. A demonstration queues behind a running background plan. The same process reuses imported libraries and any compiled DP functions between jobs. NiceGUI owns shutdown of the configured pool; database and snapshot I/O still use its separate thread pool.

The Plan action summary shows the selected mode and power ceiling, with an optional controller target in kWh and SOC percent. The target is monitored by a future controller and is not a device SOC cut-off. The same action can achieve different power across scenarios.

Plan settings edits the complete energy_plan YAML in a responsive dialog. Its Run Demonstration button validates the draft, closes the dialog and calculates a browser-only demonstration. There is no standalone demonstration button. Load Global copies the live saved settings into the editor. Save To Disk persists only energy_plan and updates the running background planning settings, with the next new full reading eligible for a shared plan. There is no separate protection preference input; edit protection_preference in the YAML. Validation errors keep the dialog open and the last valid overlay intact.

Save To Disk is a blue outlined button at the left of the settings footer. It requires confirmation, keeps the editor open and reports successful saving with a positive notification. It does not apply the draft or rerun the model. The separate Model dropdown is removed; edit optimiser.model in YAML.

The Plan next action uses a pale-blue filled panel with a small `Next X mins - As of Tue, 16 Jun 2026 11:05` caption and separate command description. The date and time are the first plan interval's start in the configured timezone. Model, override-active and missing-actuals text are omitted. Net cost in the summary grid shows the selected scenario's visible cost to three decimals plus the minimum/maximum range to two decimals, e.g. ?0.212 (-?2.44 to ?2.40), rather than a separate headline. The leading cost follows the selected Solar/Load case, matching the other summary cells; only the range covers all scenarios.

Advanced Self-consumption rows show only the mode name. Other Advanced actions show projected average **import** or **export** power and ending battery kWh/SOC rounded to whole numbers, for example `Force discharge: export 2.00 kW to 4kWh/21%`. Grid power is an outcome, not the requested battery rate. Advanced Excel uses the same action text; Compact keeps short labels.

DP Advanced detail and Excel include Limit Score for scheduled battery Min/Max breaches. A negative value identifies an interval-end breach; zero means the ending level meets the preferences. Like other scores, the browser shows an hourly rate and the footer sums original duration-weighted contributions; Excel exports those original contributions. DP Total Score includes Limit Score, while Net cost remains actual model import cost minus export revenue. Compact omits score columns. MILP retains its existing score columns and hard Min/Max limits.

Advanced detail shows projected ending kWh/SOC and grid flows for the selected policy. Zero-power variants with PV export show `Export Solar Excess` in the UI.

Mode 5 at zero discharge allows surplus solar to charge in the model; that installed-firmware response remains unverified.

Plan Settings initially displays the archived energy-plan YAML of the displayed snapshot unchanged. Loading a report does not validate that YAML against the current model configuration. Run Demonstration and Save To Disk validate the draft against the current schema and report incompatible or missing settings. Load Global explicitly replaces the draft with the current live configuration.

The Plan chart has Line/Bar power buttons on the legend row, aligned to the right. Line is the initial display. Switching affects both actuals and forecasts for Solar, House Load, Grid Import and Grid Export. Battery actuals always remain solid lines and battery forecasts dashed lines on the kWh axis. Bar mode groups power into configured-local clock hours and shows average kW: forecast interval energy is split at hour boundaries and weighted by covered duration, while actuals average available minute readings. Partial hours use available coverage; missing observations stay null, without zero filling. Repeated autumn hours retain separate UTC buckets. All bars use the hour midpoint. Actual bars are solid-coloured and forecast bars have a diagonal pattern and reduced opacity, sharing one legend toggle per metric. A scrollable legend reserves space for the controls on narrow screens. The selection is per browser and survives actuals refreshes, scenario/view changes and snapshot selection; legend toggles and zoom are preserved. This display choice does not change saved reports or settings.

Plan Download Excel uses a single `Plan detail` worksheet. Compact keeps its existing forecast/detail headings and appends comparison columns on each plan interval's row. Advanced uses 52 ordered columns: local/UTC timing and action, tariffs, adjacent forecast/actual power with coverage, battery state/targets, forecast energy, finances, routes/conversions, losses/clipping, and scores. Export variables use explicit `forecast_`/`actual_` names and unit suffixes, with readable spreadsheet headings; battery ending forecast appears once. A six-row metadata block (`snapshot_id`, `model`, `view`, `solar_scenario`, `house_load_scenario`, `report_basis`) precedes the Advanced table, separated by a blank row. Unknown metadata for demonstrations or older reports stays blank. Advanced includes Duration (min) and retains the original subtotal/total contributions. Power comparisons use average kW, with actual minute samples weighted by their overlap with that interval and coverage minutes reported per metric. No missing intervals are filled or extrapolated. Battery comparison uses the forecast ending kWh and latest measured battery reading within the interval through its end, with that reading's UTC timestamp. UTC start/end columns distinguish repeated local hours. Missing/future actuals and all comparison footer cells remain blank. Measurements before the projection or beyond the selected Compact/Advanced horizon are excluded. Export reuses the chart's loaded actuals, independent of zoom/Line/Bar display, without another database read or optimiser run.


On each new shared plan publication, `PlanTab.sync_shared_plan()` refreshes snapshot choices for the currently selected date. A blank Snapshot follows the new report, updating chart and table. A selected snapshot keeps its report and selection while the choices update; if retention removed its database entry, its existing choice remains available while pinned. Refreshes preserve selections made during a pending read and discard results for a superseded date. Service health notifications without a new plan version do not requery snapshot choices. Reconnecting browsers use the same synchronisation path.
